# V2.2 变更与验证 · 2026-11-05

## 原因与修复

1. 输入区序号01、标题、任务徽标和重复占位说明均为写死的冗余展示。移除这些节点，只保留textarea placeholder，输入时自然消失；功能说明仍在入口下，填空模板为可选折叠区。
2. 资料删除已在真实生产HTTP中复现400：Next DELETE无正文仍可产生空ReadableStream，input()无条件JSON.parse空串。新增空流回归用例，修改前400、修改后200；total===0返回空对象。修复也适用于其他无正文写请求。页内删除确认和即时列表更新保留，错误只在资料窗口顶部显示一次。
3. 先导入Markdown/TXT，再自动填入名称和正文，不需重复复制。保存后清空新增区，可继续添加。仍不支持图片和视频；未伪装模型已理解媒体。
4. 业务对象=处理的业务事情；目标用户=使用的人。新增字段小字示例，保留原字段和数据。
5. 新增页面更新日志和根目录CHANGELOG.md，解释PM+mate共享M形成PMATE。
6. 原长POST generate在页面等待且绑定请求signal，前端busy全局锁住任务。保留兼容generate，新增jobs202立即返回、独立AbortController、activity轻量状态轮询。最多两个不同项目并行，同一项目只允许一个任务。任务状态、草稿、最终文档仍在原SQLite表记录。页面刷新/切换不主动取消；停服务会中断，不承诺重启续跑。
7. 新增五类填空式User Prompt生成器、上一步文档引用选择、需求→方案→PRD衔接按钮，PRD不再自动循环到竞品。竞品随时可做，不硬锁任务。模板空字段标为待确认，不编造。
8. 截图“缺少方案结论/风险...”是专业正文标题检查失败，不是业务信息追问。每次生成强化原固定标题；非空专业稿缺结构时交最终审核整理，最终结构失败最多一次额外审核修复。仍失败保留草稿，不能创建成功文档；来源审核失败继续拒绝，不拿演示替代。标题标准化忽略Markdown装饰和连接词，保留原专业章节要求。
9. 独立代码审查发现轮询切换编辑中文档的风险：轮询不再改变编辑中的选中文档；当前项目运行时禁用版本切换和编辑。其他项目仍可阅读/编辑。

## 数据与权限

没有改表结构，无自动数据迁移或删除。保留.env.local、data和教师prompts。后台运行是当前Node进程内任务，不是跨重启的持久队列。个人版本地免密码，仍监听127.0.0.1:3020、同源写入与限流；公开部署需额外访问控制。GitHub Pages不能直接运行此Node/SQLite完整版本。

## 实际验证

- 37/37自动化测试、Next生产构建、TypeScript通过。
- 原始四类教师System Prompt保持逐字不变的回归用例通过。
- 生产HTTP验证：首页200、两份资料依次无正文DELETE并刷新列表、两项目同时后台生成、需求→方案→PRD使用同项目真实文档ID、全部版本保留。模型响应由受控fixture产生，非真实DeepSeek。
- 后台单元测试验证发起请求Abort后任务继续完成，重复项目与第三个任务被拒绝。
- 格式修复测试覆盖缺专业标题交审核、最终修复成功、最多一次修复后继续失败关闭。
- 证据日志见docs/evidence/v2.2-*。

## 限制

真实DeepSeek质量与用量未在本环境测试；Windows双击、浏览器逐项点击、手机视觉未实测。不能把受控测试当模型质量验收。
图片/视频、联网搜索、向量检索和多用户云同步均未实现。当前知识库为文字关键词检索。
报告正常三次模型调用，格式修复最多多一次，单节点120秒；后台并行不保证单份报告更快。
导入备份仍限制2MB，超过时停服务备份整个data。未提交输入不保证刷新恢复；已提交任务与文档保存在数据库。
