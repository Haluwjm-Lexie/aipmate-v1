权威来源 A：docs/sources/teacher-original.md。B：migration-reference.md 仅提供迁移与程序控制建议。

|---|---|---|---|---|

正常链路：浏览器POST /api/projects/[id]/generate → 服务端认证/同源/长度/项目访问检查 → 同项目所选历史版本校验 → 节点1 → 节点3/4/5/6之一 → 固定标题校验 → 节点8 → 固定标题/引用逐字片段校验 → 文档新增版本与运行记录。

高风险：1→2；未知：1→7；资料不足：1→保存追问；失败/取消/空结果：保留任务输入及失败记录，不写成功文档。逻辑依据A职责与B参考重建，非Coze画布精确复刻。

## 逐项变更记录

1. 原文完整保存在 prompts/original；3/4/5/6 的 System 内容逐字保持，测试直接比较原文，不用字数代替相等。
2. 1示例 safe_response_requir 修正为 safe_response_required，与正文和程序统一。
3. input/user_input/USER_INPUT 均映射 task_input；outputList 映射 retrieved_evidence。
4. 当前没有检索：retrieved_evidence 永远为空，并标注未检索。粘贴资料属于用户提供，不改称知识库证据。
5. 2原文无User模板，依据B补充最小安全摘要模板，不向2转发原资料和历史正文。
6. 8保留A的完整User要求及四分支占位符，由程序仅填命中分支，其他为空；追加当前任务、项目与真实来源清单，防止最终审校缺少证据。
7. 每个模型节点追加API传输契约：原Markdown正文置于JSON body字段。未改写专业方法、标题或正文要求；节点1保持原JSON契约。
8. 项目、历史草稿、追问、粘贴资料通过额外上下文传入每个正常节点；历史AI正文标注未确认，不作为已确认会话事实。历史仅限用户主动勾选、同项目、非演示的版本，最多3份5万字，不静默截断。
9. 程序保存Prompt版本、实际System/User消息哈希、节点、响应ID（服务商提供时）、耗时与Token，不保存密钥或模型推理过程；原专业草稿与审校稿同时保存。
10. 结构校验只认Markdown标题；缺标题或PRD无GWT则报错，不用模板补齐。审校引用 sourceId 必须存在，quote必须逐字存在于实际输入。事实真伪仍需人审，不宣称独立联网核验。
11. 百分比检查只提示输入中未出现的百分比，属于有限启发式，不保证识别所有无依据数字。
12. 保留原有DeepSeek连接与鉴权配置，不引入多模型切换；单个节点120秒，请求链可能达数分钟，部署代理超时需相应延长。
13. 表结构不变；新属性放进现有JSON记录。已有文档、运行和版本保留；备份导入保留新工作流元数据。

哈希与A原文行号详见 prompts/manifest.json。

14. 资料支持列表每条必须包含实际来源ID，并存在对应逐字引用；只有任意来源名称但无引用时拒绝保存。风险关键词规则识别紧邻的明确否定语句，避免“不绕过权限”被当成越权请求；语义风险仍由节点1审查，规则不保证覆盖全部表达。
15. 导入备份时同项目历史引用和父版本ID映射到新副本ID；不会引用另一个项目的旧ID。routing元数据保留。
