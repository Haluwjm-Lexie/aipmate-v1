# AIPMATE · AI 产品经理助理工作台 V2.3

在原 V2.0 上修复任务切换与界面，保留老师八节点完整专业 Prompt。默认使用 DeepSeek，Kimi 未接入。升级方法见 `更新说明.md`。

## 打开

需要 Node.js 24.22.1 或更新的24.x版本。保留你的 `.env.local` 与整个 `data` 目录。双击 `启动工作台.bat`，首次安装依赖需要联网。看到 Ready 后打开 **http://127.0.0.1:3020**。保持黑色窗口打开，退出时 Ctrl+C。

V2.3 本地个人版不需要登录密码，旧配置中的 APP_PASSWORD 即使保留也不再使用。模型密钥仍只在服务端读取，不会返回网页。

新配置示例：
```dotenv
DEEPSEEK_API_KEY=你的密钥
DEEPSEEK_MODEL=你的准确模型ID
DEEPSEEK_BASE_URL=https://api.deepseek.com
DATA_DIR=./data
```
不要公开 `.env.local` 或 data。正常启动只监听本机；取消登录后不适合直接公开到互联网，公网使用需要部署层的访问控制。

## 使用

1. 新建项目：名称必填（100字），业务对象、目标用户、已确认范围、关键约束、待确认事项均选填（每项6000字）；阶段是下拉单选，原有阶段保留。
2. 选择任务：智能识别、需求分析、AI方案设计、PRD草稿、竞品分析。每类有独立输入草稿与结果列表；切换不会把旧结果当作刚生成的结果。
3. 不会写要求时展开“不会写要求？用填空模板”，填你知道的，点击放入输入框。需求完成后点“采用此需求，去设计方案”，方案完成后点“采用此方案，去写PRD”，自动勾选上一步文档；不自动运行。
4. 项目背景是共用资料，默认收起；与当前选择的任务无关。阶段只是进度记录，不锁定任务。
4. 输入要求（最多20000字）；本次参考资料最多50000字；追问补充最多10000字。点击开始分析，资料不足时先补充。任务由服务端后台运行，可以切换其他项目，最多两个项目同时生成；同一项目一次一项。网页刷新后可重新查看状态，关闭服务或重启电脑仍会中断。
5. 正常生成自动保存新版本，可复制、编辑、导出Markdown、查看依据或重新生成。继续下一项只填入建议，不自动运行。
6. 最近任务右侧 × 可删除任务记录；保留已保存文档。运行中的任务应先取消。项目删除和版本删除仍需确认。
8. 连接与资料 → 测试模型连接。项目资料库可以粘贴文字或导入 UTF-8 的 Markdown/TXT；每份正文50000字、名称100字，每项目最多20份、总计20万字。

推荐顺序：需求分析 → AI方案设计 → PRD草稿；竞品分析可以在前期或任何阶段做。不会自动依次生成，也不要求必须先完成前一步。

## 模型、资料库、搜索是不同能力

- 模型连接：DeepSeek生成和审核；测试会产生一次小额API调用。
- 项目资料库：本地保存授权资料，按任务中的中英文关键词检索，取最多5个相关文字片段传入模型。保留真实来源ID与逐字引用。不匹配则明确记录无匹配，不塞入虚构来源。这是基础文字检索，不是向量知识库。
- 联网搜索：本版本未实现，不会因模型连接成功就显示已启用。只粘贴网址不会读取网页。状态集中在连接与资料，不重复出现在任务说明下。

## 数据与备份

SQLite仍为 `data/workspace.sqlite`，没有改表结构。新增项目资料使用原项目JSON记录中的knowledge字段，旧项目自动兼容。导出备份包含项目、资料与文档，不含密钥和任务日志；导入创建副本，不覆盖。导入上限2MB、100个项目、每项目300文档。

升级前停服务，复制整个旧目录（或至少 `.env.local` 和整个 data）留作备份。运行中不要单独复制 sqlite 文件。未提交的输入草稿只在页面会话中保留；刷新可能丢失，已提交任务可从最近任务打开。

## 检查与生产运行

```powershell
npm.cmd ci
npm.cmd test
npm.cmd run build
npm.cmd start
```

本地开发 `npm.cmd run dev`、双击和生产本地模式均使用3020。Docker/Compose端口也是3020，数据库必须挂载持久化目录，单实例运行，代理需允许约400秒请求；公网须另加访问控制。不支持仅部署在 GitHub Pages。

完整Prompt、八节点映射和历史诊断见 `prompts/` 与 `docs/`。真实模型A/B可运行 `npm.cmd run compare:live`，会产生模型费用；没有密钥时不运行。不把受控响应测试当作真实输出质量评审。

## 需要特别理解的事情

- AIPMATE = AI PM（AI Product Manager，AI 产品经理）+ mate（伙伴），即“AI 产品经理的工作伙伴”。
- 业务对象是处理哪类事情（例如网页批注）；目标用户是哪些人（例如学生、职场人士）。
- 图片和视频当前不支持导入分析，需要OCR/转写等额外能力，不能当作文字资料直接检索。
- 模型正常需要识别、专业生成与最终审核三次调用；报告格式缺失时最多额外整理一次。这不等于真实业务资料不足，失败时可以展开未通过检查的草稿。
- Github Pages只适合静态演示，完整AIPMATE需要Node服务与持久化数据库；不能把API Key放进静态网页。
- 查看界面“更新日志”或根目录CHANGELOG.md可了解各版变化。
